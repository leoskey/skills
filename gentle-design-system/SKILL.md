# 柔和极简数据风

将六张参考稿的共同视觉语言迁移到用户的产品，而非复制 HVAC 利润业务。默认浅色桌面数据界面；移动端、交互状态和实现 token 是为复用补充的规范，并非原稿实测。

## 使用方式

1. 确认当前任务的页面、数据、技术栈及既有组件。用户已经指定的功能和品牌优先。局部修改只应用相关规则，不顺带重写应用。
2. 阅读 [基础规范](references/foundations.md)，以 [tokens.json](assets/tokens.json) 为数值来源。Web 可导入 [tokens.css](assets/tokens.css)；Flutter 阅读 [平台映射](references/platforms.md)。这些是建议起点，不是截图的原始设计文件。
3. 按任务读取 [组件](references/components.md)、[图表](references/charts.md) 或 [页面配方](references/layouts.md)，不要为简单改动加载全部资料。需要比较视觉时，阅读 [设计来源与预览](references/source-index.md) 并查看重新设计的示意图。
4. 用语义 token 和复用组件实现；先建立壳层、标题、卡片和数据层级，再调整装饰。没有真实数据时显式标注演示数据，不能生成看似真实的预测、置信区间或收益承诺。
5. 在目标宽度检查实现。用 [验收清单](references/quality.md) 核对比例、状态、可访问性及图表表达；有运行环境时实际渲染检查。交付说明已验证的内容与未验证的限制。

## 必须保留的视觉特征

- 灰白同色系壳层与卡片，1px 细边框、约 20px 卡片圆角；页面以留白和对齐分组。强阴影只用于浮层，日常卡片不做悬浮堆叠。
- 窄侧栏、深炭色选中项、左对齐大标题；数字比标签更突出，表格与图表采用等宽数字。
- 蓝色表示实际值、保留值或交互状态；洋红表示流失或不利偏差；绿色表示改善或达标；橙色表示风险或提醒。涨跌箭头的颜色由业务含义决定，不能机械地“上涨为绿”。
- 图表强调直接标注、虚线目标、轻网格，以及斜线纹理与实心末值的对比。纹理应裁切在数据形状内，颜色不能成为唯一编码。
- 深蓝到浅蓝、暖杏色的渐变只用于少量洞察／建议卡片，正文置于稳定的深色区域。一个可见页面通常只需一张。
- 信息链为“现状 → 原因 → 证据 → 动作／模拟结果”。动作文案说明对象和效果，而不是统一写“了解更多”。

## 迁移边界

保留目标产品的名称、实体、导航和数据含义。邮件产品可将利润指标替换为处理量、响应时间或待处理分类，但不得仅为套用颜色而虚构损失、风险或增长。不要把截图的 margin 标识、客户名、人员头像作为新产品资产。

截图上的播放三角、鼠标指针、压缩模糊、外部展示背景都不是组件。第 5 张的暗色遮罩仅代表模态框打开状态。未提供暗色主题；用户需要时应单独设计与验证，不能简单反色。
