# Adobe Spectrum Design System

将 Spectrum 2 用作产品界面的设计依据，而非把官网展示页复制成业务界面。本 skill 是独立整理的使用指南，不是 Adobe 官方发布包，也不附带 Adobe 专有字体、图标或完整 Figma 资产。

## 工作方式

1. 先确定目标平台、主要任务、已有组件与技术栈。区分“找资料／看 demo”“视觉审查”和“实现界面”；前两者不自动触发项目改造。
2. 按 [官方资源与版本](references/official-resources.md) 查阅当前规范。新任务以 Spectrum 2 为起点；已有 Spectrum 1 项目不静默混用或升级。实施前核对实际安装版本、组件 API 与 token 名称，不把本指南中的链接当作永久不变的 API。
3. 先组织应用壳层、主内容与辅助面板，再选组件和表面样式。信息密集的桌面界面按 [桌面布局与验收](references/desktop-and-quality.md) 设计；内容浏览界面则按任务选择列表、卡片或画布。
4. 优先复用项目已有主题系统，将官方语义 token 映射到颜色、尺寸、字体和状态。React 项目可选择 React Spectrum；非 React 或原生平台保留其框架与平台习惯，不为套风格强行重写。
5. 实际渲染并检查目标窗口、主题与交互。交付时区分“规范已查阅”“静态视觉已检查”“交互已运行”“真实业务已接入”，不把组件 demo 或概念图当成完成的应用。

## 设计判断

- 主内容应获得主要注意力，导航和工具栏为操作服务。通过对齐、分组、表面层级和必要的分隔建立结构，避免每块内容都争抢注意力。
- 颜色使用语义角色，区分背景、文本、边框、强调与状态。错误、警告、完成、禁用和选中不能只靠颜色区分；不把某个品牌色当作所有业务状态。
- 使用同一版本的字阶、间距和组件规格。不要凭截图估算一组数值后标为官方 token；自定义补充值须明确标记并解释用途。
- 对按钮、输入、表格、菜单和浮层覆盖默认、悬停、按下、焦点、禁用、错误与加载等适用状态。明确操作对象、可用条件及完成反馈。
- 深浅主题分别检查文字、图标、分隔线、浮层和选中状态，不简单反色。字号与点击区域服从目标平台与可访问性，而不是一味压缩。
- 渐变、阴影与材质不能替代信息层级。未经许可不复制 Adobe 品牌资产；需要自有品牌扩展时说明它是产品定制，不冒充官方 Spectrum 规范。

## 范围与使用

只修改本次指定页面、组件或设计规则，保留业务字段、导航语义和未授权的现有流程。演示数据显式标注；不将某个示例应用、行业或个人工作流写成产品需求。

调用示例：

- “使用 $adobe-spectrum-design-system 设计一个数据管理工作台，保留现有技术栈。”
- “按照 $adobe-spectrum-design-system 审查这个界面的层级、信息密度和键盘操作。”
- “使用 $adobe-spectrum-design-system 查找 TableView 的官方 demo 与当前 API，不修改项目。”
