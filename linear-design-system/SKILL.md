# Linear 风格设计系统

将 Linear 的视觉语言应用到目标产品。依据实际内容选择页面结构，不把示例导航、演示数据或某个应用的实体变成新项目的需求。本包为独立整理的实现指南，数值是参考起点，不是 Linear 官方完整规范。

## 使用流程

1. 确认本次是产品工作区、展示网站还是局部调整。读取现有代码与用户提供的视觉参考；已有项目先查看运行界面，保留业务、技术栈和有用的交互。合理推断常规实现选择，无须为间距和布局逐项询问。
2. 阅读 [基础与布局](references/foundations.md)，以 [tokens.json](assets/tokens.json) 为参考值。Web 可按范围引入 [tokens.css](assets/tokens.css)，其他平台映射到既有主题；不要强制替换组件库。
3. 按需阅读 [组件与交互](references/components.md)。记录型界面优先建立侧栏、列表、详情与滚动边界；展示网站优先建立内容叙事、标题层级和产品展示。二者使用不同的内容密度。
4. 用语义 token、复用组件和真实状态实现。未接后端时说明数据的保存范围；演示指标须标注为演示，不将示例当作业务事实。按钮、筛选、菜单和提交必须具有与文案一致的行为。
5. 按 [视觉与交互验收](references/quality.md) 实际渲染检查宽屏、中间宽度与手机，修复观察到的问题。报告实际验证结果、截图位置和未验证项；构建成功不能代替视觉验收。

需要了解设计来源、`getdesign` 命令或素材边界时，阅读 [来源与维护](references/sources.md)。[概念预览](assets/preview.html) 用于比较视觉语言，不是完整业务模板。

## 必须保留的视觉特征

- 近黑画布、深炭色工作面与轻微表面层级，主要使用 1px 细边框分区。阴影集中于菜单、对话框等浮层。
- 蓝紫色只强调主要操作、焦点或必要状态。红、黄、绿等颜色保留业务语义；状态同时具有文字或图形，不仅靠颜色表达。
- 产品内导航和列表紧凑、左对齐。通过字重、字号、间距和适度明暗区分标题、正文与元数据，避免把所有次要信息压到不可读。
- 列表与详情形成连续的工作面，不将每一段文字包装成卡片。只有需要聚合的建议、摘要或输入区域使用边框容器。
- 优先保持用户任务与主要动作可见。桌面可并排查看列表与详情；手机按任务切换，并提供明确返回入口。
- 动效短促且用于表达状态变化，遵守减少动态效果偏好。不要为了制造风格添加玻璃模糊、彩色光晕或无关动画。

## 边界

用户指定的截图、设计文件、品牌、语言和内容要求优先。不要默认改为英文、添加某个公司的名称或复制示例人员、项目和指标。截图外框仅用于展示，不要求产品本身带设备边框。

本包包含深色参考值；浅色模式需要另行映射和验收，不能简单反色。高保真复刻与“受 Linear 启发”是不同目标，应按用户任务确定，不把第三方参考值描述为官方精确规格。
