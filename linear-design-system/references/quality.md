# 视觉与交互验收

## 有界检查流程

1. 修改已有项目时先查看有代表性的运行页面。记录主要任务、内容密度、滚动与选中状态；有用户截图时，用相同宽度与状态对照。
2. 实现后在桌面、发生布局变化的中间宽度和手机检查实际截图。建议从 1365×762、900×800、390×844 开始，再按目标设备调整。
3. 每轮基于观察修正明确问题，最多进行三轮有界视觉修正。达到范围内标准即可交付；环境不支持渲染时明确报告，不能用源码检查冒充截图验收。

## 视觉检查

- 主要任务和主要动作一眼可辨。页面标题、行标题、正文和元数据的层级明确，密度符合产品工作区或展示网站的用途。
- 侧栏、列表和详情比例合理；不存在不必要的超大固定容器。检查各层的滚动宽度、溢出与固定元素遮挡。
- 长标题、多行正文、长链接、大量记录与空内容均不撑破布局。字体加载失败时回退仍可用。
- 采集关键元素的实际字体、字号、行高、字重、色值和包围盒；验证本地字体确实加载，而不是只检查字体声明。
- 普通文本对比度目标至少 4.5:1，大号文本与必要控件图形至少 3:1。实际复合背景上测量；不能只因为用了参考 token 就认定合格。

## 交互检查

只验证本次实现的能力，但覆盖其实际状态链：

- 选择记录后详情变化；筛选有匹配与无匹配结果；返回列表保留必要上下文。
- 创建或编辑记录后，列表与详情一致；重载后的保存行为符合产品声明。
- 评论空输入、正常提交与失败恢复符合预期；提交内容没有作为 HTML 执行。
- 暂缓与恢复使用真实时间状态；归档行为具有可理解的结果。相关建议不能引用当前记录自身。
- 搜索能找到实际记录；Enter、方向键、Escape 等快捷操作不与输入行为冲突。
- 菜单和对话框具有可访问名称，焦点可见且不被遮挡，按预期管理焦点与恢复焦点。对话框内焦点不能落到背景。
- 指针目标至少 24×24 CSS px，或符合 WCAG 2.2 的间距等例外；触屏主要操作通常宜为 44px。状态不能只用颜色编码。
- 减少动态效果时仍能完成任务。若有网络，检查等待、错误和不可用情况；纯静态原型不添加无意义的模拟加载。

## 交付证据

记录采用的风格配置与理由、实际查看的视口和状态、截图位置、关键测量、实际运行的交互、构建或语法检查，以及未验证项。真实后端、演示数据、本地保存与附件能力应分别说明。

仓库概念预览用于说明视觉规则；它不是接入真实业务的产品，也不能代替目标项目的验证。没有进行真实用户或辅助技术测试时，不声称通过完整可访问性审计。

参考：[WCAG 2.2 文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[点击目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。
