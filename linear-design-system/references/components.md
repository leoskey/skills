# 组件与交互

## 导航与工具栏

导航项含图标与标签，以低对比度背景和适度字重表达选中，不默认使用大块蓝紫填充。分组标签比项目文字更轻，但仍需可读。根据目标信息架构配置导航，不要求沿用参考产品的菜单名称。

工具栏承载当前上下文、少量高频操作与更多菜单。只使用图标的按钮提供可访问名称、悬停提示和焦点态；点击目标不能缩到图标本身。菜单支持方向键、Escape、焦点恢复；对话框支持标题、焦点管理和键盘关闭。

## 列表与详情

- 行由主标题、必要元数据、状态与少量辅助信息组成。桌面可从约 44–60px 行高调整，触屏根据阅读和点击面积加大。
- 仅在列表中截断长标题；详情展示完整标题并允许换行。避免列表内左右内容互相挤压。
- 未读、选中与处理完成具有不同含义，分别建模。打开一项是否标记已读由产品需求决定，不能误当作关闭记录。
- 列表筛选具有可见当前值。空结果应区分“没有记录”和“筛选后没有匹配”，提供适用的恢复动作。
- 详情先呈现标题与描述，再放辅助建议、活动和评论。不要让元数据抢过正文层级。

## 建议与状态

建议区域可用 1px 边框和轻微表面提升，与正文保持联系。建议标签、状态标签与实际执行按钮应有清楚区别。

关联或重复建议必须与当前记录相关；不能让所有记录显示同一条建议，不能把当前记录推荐为自己的重复项。接受建议要更新模型并给出反馈；没有建议时显示合理空状态或隐藏该区域。

状态、优先级、标签和负责人按目标数据模型决定。改变状态后，列表、详情和筛选结果同步更新。颜色表示含义时同时保留文本、图标或可访问描述。

## 评论与创建表单

- 空评论不允许提交；有内容才启用发送。提交后保留作者、正文与时间，错误时保留输入并允许重试。
- 评论内容作为文本安全呈现，不直接插入未经处理的 HTML。保留换行，长单词和链接不得撑破容器。
- 使用创建表单时，标题为必要字段；保存后新记录应能从相应列表找到。不要显示成功提示但没有实际状态变更。
- 仅在获得目标文件保存能力时声称上传完成。添加附件名称与上传文件是不同的行为，界面文案应明确。
- Cmd/Ctrl+Enter 发送、单键新建或 `/` 搜索是可选惯例。不能在输入框内截获普通字符，不能覆盖已有应用快捷键。

## 本地原型与生产实现

| 能力 | 本地原型 | 生产实现 |
| --- | --- | --- |
| 数据保存 | 可使用 localStorage，说明浏览器范围并处理存储失败 | 使用已有数据层与访问控制；显示保存状态与失败恢复 |
| 暂缓通知 | 保存截止时间，恢复时检查，说明刷新或重新打开后生效的边界 | 使用后端或可靠调度，处理时区、幂等和跨设备一致性 |
| 归档 | 从当前列表移出，按范围提供撤销或归档视图 | 与服务状态同步，错误时恢复 |
| 搜索 | 对实际模型做匹配，支持空结果和键盘打开 | 接入已有搜索，处理等待、分页、取消和错误 |
| 指标 | 明确为演示数据，不承诺实时更新 | 从实际数据计算，展示口径和时间范围 |

这些是能力边界，不要求每个界面都具备表格中的所有功能。只实现用户要求及使它们合理工作所需的状态。

## 反馈与动态效果

悬停和选中通常用轻微表面变化，短过渡约 100–160ms。保存结果使用非阻断反馈，错误说明后续动作。遵守减少动态效果偏好；无动画时仍能理解状态变化。
