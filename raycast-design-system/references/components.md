# 组件与交互

[components.css](../assets/components.css) 是小型 Web 样式起点，不包含完整状态管理或组件框架。已有组件库应映射 token，而非并行引入另一套组件。

## 搜索与命令面板

- 输入框明确搜索范围：当前集合、某个类别或全部内容。无结果时提供可执行的下一步；范围受限时允许扩大范围，不能只说“换个关键词”。
- 将输入值、过滤结果、选中项和焦点分开管理。输入值更新不应清掉无关编辑内容。
- ↑ / ↓ 更新当前项，↵ 执行默认动作。只有约定明确的命令面板采用这些快捷键，避免抢占原生输入和选择控件。
- 切换选中项后保持它在结果区域内可见，例如 Web 使用 `scrollIntoView({ block: 'nearest', behavior: 'instant' })`。不能只更新旁边的详情内容而让列表停在顶部。
- 当前项无效或结果变空时明确处理默认操作、当前位置与空状态，避免执行已不在结果中的对象。
- 原生应用使用其平台的快捷键约定；Web 需要处理 macOS Command 与 Windows/Linux Control 的差异，并让鼠标或触屏有等价入口。

## 列表与详情

行内顺序可采用“图标 → 主标题 → 辅助信息 → 状态或动作”。不是每一行都需要全部元素。选中态使用中性色，未读或重要项采用文字与图标等补充线索。

选中、焦点与已读状态分别更新。重绘或删除当前元素后，将焦点保留在同一操作或合理的相邻位置；不要默默落回页面根部。保留与当前任务有关的滚动位置。

详情区域避免把导航、标签、正文和操作都装进同样的卡片。长文本使用稳定的正文色与行宽；内容附件保留自身色彩，外部控件随主题变化。

## 按钮、输入与浮层

- 主按钮使用 `brand / on-brand`。次要动作使用中性表面；低强调动作使用文字或幽灵按钮，不能把所有动作都做成珊瑚红。
- 图标按钮需要可访问名称；不易识别的图标优先加可见标签。禁用说明动作为什么暂时不可用，不只改变透明度。
- 输入覆盖默认、焦点、错误、只读和禁用等适用状态。辅助提示、字段错误和提交反馈与对应控件关联。
- 可以把复合编辑器的焦点显示在容器上，例如 `.rc-composer:focus-within`；去掉内部 outline 前必须有这个可见替代。
- 对话框优先使用平台原生机制。打开时焦点进入有意义的控件，关闭后回到触发处；Escape 等关闭路径服从内容保护规则。
- 菜单、对话框和 Toast 使用与当前主题一致的表面、边框、文字与焦点。提示不是恢复路径的唯一长期入口。

## 需要编辑内容时

这些规则仅适用于有输入或编辑任务的界面，不要求浏览类页面增加编辑器。

- 草稿数据独立于呈现节点。星标、标记、筛选、主题切换和重绘不应使输入丢失。
- 根据产品范围选择本地草稿、服务端草稿或关闭前确认。若显示“已保存”，要对应真实完成的存储；存储失败时保留内存内容并说明当前能力。
- 离开、返回、关闭与重新打开的路径与正常提交同样需要测试。发送或完成后清掉对应草稿，不留下过时内容。
- 需要跨刷新或跨设备恢复时，明确数据生命周期和隐私边界；不能把仅保存在当前页面内存的内容描述为已经持久化。
- 表单修剪空白后若无有效内容，应有明确的字段反馈，不能无声地返回。高频多行输入可按平台约定提供 Command / Control + Enter。

## 可逆操作与状态

删除、移出、归档等动作应按实际语义提供恢复。短时 Toast 撤销能加速操作，但不能替代废纸篓、历史或原位置恢复入口。保存原位置等恢复所需信息，不把“恢复”悄悄解释成移去另一个集合。

加载、无结果、空集合、错误、成功和离线仅在业务实际存在时设计：保留可用内容、说明当前状态，并给出对应的下一步。不要为纯本地展示伪造网络同步或业务成功。

## 动效

建议起点：悬停、按下和颜色 120ms；菜单、Toast 和状态过渡 180ms；窗口过渡 240ms。缓动 `cubic-bezier(.2,.8,.2,1)`。高频输入与选择及时反馈，不逐项延迟出现。遵循减少动态效果设置。
