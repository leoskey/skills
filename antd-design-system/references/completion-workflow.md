# 全目录补齐与逐页验收

用于用户要求“补齐计划”“继续补齐其余页面”或全面覆盖官方后台时。普通单页任务仍按所选页面模式完成，不自动扩成全站项目。

## 先确定覆盖范围

从目标提交的config/routes.ts提取实际页面；重定向、带子路由的容器、通配回退分别列出。当前3.2.0的复核与历史跨环境/状态矩阵见[扩展验收](expanded-acceptance.json)，当前模板覆盖快照在 [page-coverage.json](page-coverage.json)：27个独立页面，模板已逐页实施并保存对照与状态证据；最终人工认可均待用户决定。快照只代表当前模板，不能覆盖用户项目自己的状态。

用户只要求计划时，交付页面清单、依赖、顺序、逐页验收合同和证据复核结果；不把计划状态写成实现完成。用户同时要求执行时，先保存计划，再按依赖分批实施，每页修正、验收、更新记录后推进。不要把一轮的示例页数量当作永久范围。

## 状态应分开维护

- implementation：missing（未实现）、simplified（简化示例）、complete（对应模式完整）。以实际路由/模块为依据，不能因访问任意同前缀路径会返回基础页而认为高级页已实现。
- visualAcceptance：not_run、failed、agent_reviewed、agent_reviewed_with_documented_difference；原始几何通过与否单独记录。沿用旧证据时标注previous_evidence与版本/日期、适用源码。没有截图、基准或真实内容时不写通过。
- humanAcceptance：pending或accepted；只有用户的明确认可才改变。

## 推进顺序

先建立路由与共享组件，再逐页推进：复杂表单 → 列表变体/共享搜索容器 → 详情/结果/异常 → 工作台/监控/个人 → 独立认证页 → 欢迎/管理/AI助手。可以按用户业务优先级重排。每批更新模板与回归共享壳层；不等待全站结束才记录验收。

官方源码目录、子组件、样式、mock、依赖与许可证一起核对。Umi运行时、API请求、随机/时钟/流式数据替换成明确的本地适配；已存在项目保留自己的构建与路由。地图或Ant Design X需要的新依赖先核对本地类型与官方版本，不能把图表/AI区域替换为空白或静态灰块后宣布还原完成。

## 每页验收合同

1. 记录路由、模式、参考URL/截图、代码/视觉版本、CSS视口与状态；列出该页关键模块和必查交互。复用原站已有缺陷时注明，不用几何通过掩盖可用性问题。
2. 桌面1280×720、浅色、100%缩放、同菜单/展开状态、同字体加载、同scrollY对照；长页分首屏/下半页，Tabs/步骤/子设置视图分别覆盖。按当前范围另做390/768/1024真实浏览器视口配对及主题、侧栏、缩放方法检查；iframe与原生缩放的替代证据必须如实标注。
3. 先审截图中的构图、组件完整性与文字/图表，再用 [compare_geometry.py](../scripts/compare_geometry.py) 比较关键锚点（本次精确复现默认2px）；字段/列宽与行密度都应测量，不只测外框。几何输入的cards数组兼容非卡片锚点，以唯一title命名。截图审阅与交互结果仍需单列。
4. 对照实际业务状态：校验/空数据/加载/错误、排序分页、弹层焦点、返回保值、选中/禁用、长文本、必要的窄屏滚动。固定mock，记录时钟起点与动画采样范围；外部业务仅本地模拟，不使用真实付款/注册/消息/模型服务来完成视觉验收。
5. 保存截图、几何原始值与比较报告、交互结果、可接受差异和未验收项。失败页修复后重验；更改共享样式/主题/路由后回归四个基准页及受影响页面。
6. 更新page-coverage状态和证据引用、页面模式/React集成、可运行模板/锁文件/来源/许可证、安装副本与ZIP。检查文档链接和安装/打包哈希一致性；保持技术、交互、视觉及人工认可各自的结论。

推荐证据目录为 `visual-qa/<page-id>/`：reference/candidate首屏与下半页PNG、geometry JSON、comparison JSON、states JSON、mobile PNG。项目可以沿用现有目录，不为命名规范移动已有有效证据。

## 全站收尾

独立页逐项完成代理审阅，几何通过、保留行为差异及旧证据分别报告；共享搜索容器、设置子视图和两类404回退有覆盖；深链接、重定向、菜单选中与刷新正确；没有同前缀兜底误映射、占位内容或无反馈入口。全站构建与关键交互通过后，提供总表及逐页报告。人工最终认可仍按每页或用户明确给出的整批认可维护。
