# 视觉验收

代码检查验证可运行性；交互检查验证行为；视觉验收验证与所选设计基准的结构、比例和细节。

## 基准准备

选择同类型官方页面或用户参考图，记录版本/提交、URL、日期、视口。实现前列出模式和关键锚点。对齐CSS视口宽高、缩放、导航状态、主题、字体加载和数据状态；不能仅把不同宽度截图缩放成同样尺寸。

固定本地演示数据。线上随机图表比较布局、轴、配色、图例与交互；动态数值和动画不构成整体像素相似度承诺。

## 检查顺序

| 阶段 | 检查对象 |
| --- | --- |
| 骨架 | 顶栏/侧栏、内容起点、是否应有PageContainer标题 |
| 组合 | ChartCard微图/footer、图表/排名、搜索/工具栏、表单分组 |
| 尺寸密度 | 栅格宽、gutter、卡片/图表高、模块起点、可见行数 |
| 细节 | 字体/字重、颜色层级、阴影、边框、圆角、图标基线 |
| 状态 | hover、选中、错误、加载、空数据、弹层、长文本、窄屏 |

先修骨架与组合，再修细节。出现漂移时先检查reset、字体和组件版本，避免靠全局缩放掩盖问题。

## 证据与阈值

保存基准/结果截图、真实viewport、关键DOM几何、差异说明。`scripts/compare_geometry.py` 比较同名锚点；默认2px容差适用于本次精确复现，普通无参考业务设计不套用固定坐标。

分析页1280×720基准：顶栏56px、侧栏256px；四卡x=296/534.25/772.5/1010.75，y=88，宽214.25，高237；销售区x296/y349/宽929/高412；下方双卡y785、宽452.5、间隔24。版本或字体导致偏移时解释差异并判断任务是否允许。

几何通过仍需看截图，脚本无法发现空白canvas、错误字体、图表色或误导文案。修复可见问题后复核受影响结果。分别报告构建、交互和视觉证据，不把人工最终认可写成已完成。

## 响应式与交互

至少检查桌面基准和一个手机宽度，确认侧栏切换、卡片堆叠、日期工具区、表格容器滚动和长文本。测试当前任务的Tabs、日期、渠道、分页/排序、表单校验、弹层焦点与键盘操作。

工具不能调视口时，可用固定宽iframe验证本地响应式，并明确这是iframe证据；桌面并排对照仍需相同真实viewport。交付说明验证范围和未检查项。

基准与候选各保存首屏和下半页；记录受测锚点数量、最大偏移和截图审阅结论。三列Descriptions必须比较每列x/width，不能只比较外框。表单必须检查手机宽度，精确还原须记录官方md/xl字段在窄屏的自然宽度及越界，不默认加入100%钳制。列表排序参数可能含未激活列，只有有效ascend/descend才排序；过滤先于切页，总数对应过滤结果。

完整模板覆盖27个官方页面及其导航层级；按业务裁剪时保留实际可用的入口。官方线上随机数据、源码/视觉版本与本地页脚差异在逐页报告声明。几何阈值通过不等于全页像素一致。

## 全目录模板补充

- 27个独立页使用精确路由，认证页不带后台壳层；共享搜索、个人中心3个Tab、个人设置4个视图也分别取证。
- 每页截图与原始测量在assets/visual-qa，索引见其中index.html；当前覆盖结论见page-coverage.json。版本/数据差异必须明列，不能把几何原始失败改写成零差异。
- 必须等待真实内容；骨架、空白、官方服务偶发空响应不能覆盖此前有效基准。比较脚本拒绝空锚点，并检查字体、壳层与scrollY。
- 390px的body宽度通过仍不足以证明可用：还要看Select实际宽度、Card.Grid列数、表内滚动、输入与底部按钮、导航与弹层位置。
- 过渡时间缩至极短值仍会对left/top测量产生插值。减少动效应禁用过渡，并实测菜单、日期、Select定位与选择反馈。可参考[上游定位问题说明](https://github.com/react-component/trigger/issues/618)。
- 所有本地认证、注册、资料、安全绑定和AI状态与真实服务分开记录；最终人工认可始终独立。

## 跨环境与状态矩阵

当前范围、逐项结论及原始失败见[扩展验收](expanded-acceptance.md)与[状态矩阵](expanded-acceptance.json)。全站验收按27页×桌面/手机390/平板768与1024/缩放等效125与150，后台24页×深色/折叠侧栏列出；认证页的后两项不适用。只完成本地手机检查不能记成与官方配对通过。

每组记录实际CSS viewport、DPR、scrollY、内容/加载状态、字体、主题、侧栏宽度、完整弹层和参考传输条件。切换标签后等待绘制；截图中的黑色缺块与真实背景色不符时重新拍摄，不能因两边都有缺块而验收。模态关闭后等动画结束，再用当前可见对话框与控件验证状态；不要点击隐藏旧模态按钮。

长页以有重叠的分段覆盖到实际内容底部；当前使用600px间隔和720px视口。只拍首屏和最后一屏不能代表中段。内容不同先区分数据、版本与布局；随机“万”导致行高不同，应另拍相同指标的诊断案例，同时保留现场原始失败。

需要固定团队/指标、空结果、流式或错误时，可以在隔离浏览器以明确记录的测试传输驱动官方UI。保留官方DOM、样式与组件；声明模拟了哪条请求、是否限速、如何恢复。严禁将测试传输截图写成未干预的线上结果。官方无处理函数或行为无法进入的操作列出源码和实际响应；本地扩展另列，不能虚构相同完成态。

缩放必须记录方法；本模板125%与150%使用等效CSS viewport+DPR，不声称原生浏览器菜单缩放通过。视觉、几何、业务行为、真实服务、实体设备与用户认可分开维护。

## 完整重验规则 3.2.0

当前原301组全部有3.2.0证据，见[逐项映射](../assets/visual-qa/full-3.2/original-301-coverage.json)。额外回归不能抵充原始ID；当前状态不得再标沿用3.1.0。保留旧原图/测量，不用重命名或改版本标签冒充重拍。

测量包含实际输入、文本域、日期宽度和头像；只测Card/FormItem外框会漏掉字段钳制。统一自动聚焦后的scrollX，记录真实滚动值。固定Footer可能挡住字段，操作前滚入可见区，提交后必须观察成功/错误，不把等待超时当完成态。

主题、数据、内容与行为独立核验。深色检查实际内容卡片背景，折叠测量侧栏64px。截图中的黑块、网络错误、骨架或恢复后错误主题均重拍，几何相同不能盖章。筛选数据使用相同公开mock与参数，标明传输条件；随机数和数据标准化不是CSS修复。

390px固定CSS视口，无mobile自动缩放；本地保留可访问缩放，官方meta禁缩放。125/150%为等效CSS视口+DPR。官方无处理或重试仍失败时保存真实不同状态，不能虚构同一完成态。原生菜单缩放、实体设备、真实服务与用户认可独立。
