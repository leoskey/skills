# VAR LIVE 品牌设计

把同一套品牌规则落实到当前项目的原生组件。此包是跨平台设计依据，不是待移植的 HTML 应用。默认保留项目的产品定位、语言、业务结构与现有依赖。

## 开始时读取

1. 阅读 [设计依据与资源](references/brand.md)、[组件规范](references/components.md) 和 [设计变量](assets/tokens.json)。颜色、尺寸以 tokens 为准；截图是构图参考，不是逐像素规格。
2. 查看 [管理界面参考图](references/desktop-preview.webp)。这是用系统字体制作的第一版演示；后续使用包内字体与可读性规范，允许文字换行与密度不同。
3. 按项目读取一份适配说明：[Flutter](references/flutter.md) 或 [Web](references/web.md)。其他技术直接映射同一份变量与组件规则，不引入 WebView 来复用参考网页。

## 品牌不变项

- 深黑背景、分层灰色面板、白色文字、橙色主操作。橙色用于主操作和选择状态；成功、危险等状态有独立语义。
- 正文使用包内 Noto Sans TC，常用字重 400 / 500 / 600 / 700。遵从项目语言；简体或其他文字若有缺字，选择相应 Noto 区域字体并在各端固定同一版本，不能静默依赖系统回退。
- 小圆角、细描边、规整网格。斜切或三角仅用于品牌识别与局部强调；不让正文、输入框和整张页面倾斜。
- Logo 使用原始素材，保持比例，不重绘、不拉伸、不改色。包内白色 Logo 适用于深色背景。
- 品牌外壳固定，游戏主视觉可变，联名视觉单独配置。海报只放在相关游戏内容中；通用 ERP、人员或财务页面不需要游戏图片。

## 实现

- 先检查已有主题、字体、图标、组件、调用方和响应式规则。优先修改公共主题与已有组件，避免散落硬编码或平行创建另一套 UI 库。
- 把需要的 tokens 映射到项目的 CSS 变量、Dart 常量 / ThemeExtension 或其他原生主题层。只实现本次页面需要的组件。记录使用的包版本。
- 字号和尺寸是 CSS px / Flutter 逻辑像素，不按设备像素比二次缩放。保留系统文本缩放；紧凑桌面与触控使用不同命中区域。
- 复用项目现有图标体系；没有时使用 assets/icons 中的 24×24 线性 SVG。不得为几个图标引入整套组件库。
- 页面内容取自当前项目。不要迁入参考图的营收、门店、帐号、人数、时长、设备数量和年龄限制；确需演示数据时明确标注。
- 只复制所需素材；复制字体时同时携带 OFL.txt。对包内文件的引用须解析为本机路径，目标项目不得依赖开发者个人目录或运行时访问此 Skill。
- 此包以深色为基线。如果项目明确要求浅色，保持品牌橙、字阶、布局和组件结构，另行定义并检查浅色语义映射，不直接反转全部色值。

## 验证与交付

按当前任务检查代表页面：桌面、窄屏、长中文、空状态，以及按钮 / 输入框的禁用、焦点、加载、错误状态。状态不能仅用颜色表达。正常文本对比度至少 4.5:1，必要控件边界与焦点至少 3:1；装饰分割线不替代控件边界。

有可用预览时对照参考图检查层级、品牌配色、字体、圆角与图标，而不是强行复刻管理总览结构。无法运行某个平台时说明具体未验证部分，不声称像素级一致。

交付已实现的项目页面与验证结果。用户未要求部署时不发布；不把品牌 Skill 的使用理解成重构全部项目的授权。

包结构检查可运行 `python scripts/validate.py`。该检查不替代页面的交互或渲染验证。
